reading textbooks in the backyard and taking detailed notes, and speaking to 
real developers and former engineers of Google/IBM/Meta.

At the time I was doing zoom calls with my mom's cousin, Richy, who is a 
former IBM Executive of many years.

To learn database/server/front-end development I built my first full stack 
app in 2022:

  • A "Social Media for Book Lovers"
    • Users have a private bank of "notes" for all the books they read
    • Users have a public discussion board to create new "topics" and 
      "discussions" for any book in our DB (using Google books DB)
    • Private groups for "book clubs"
    • Full messaging and reply system fully working incl a login security class

What was Richy's number 1 suggestion?:
A welcome-quiz.

connections of how the "user" obj integrates with the "sub-message" obj and

4. Data Strategy Discussion
====================================

There is a reason when learning full stack software engineering between 
2021/22 (and honestly I did some cool coding work in HS and I'm still 
learning every day still) the phrase I heard repeated most was "data is the 
new gold."

(Obviously a few years passed and people forget as we focus on the advantages 
poised by LLM-designed tech)

But our organization of our "user journey data" and insights we focus on can 
drive our "sales optimization" to an exciting point. Ultimately with our 
approach on data the focus is on

"Ethical Practices"
    meaning we collect:
        1. basic device info (ios, os v, etc.)
        2. IP address. (requires no permissions, additional steps, is always 
           "public" in any server call anyway)
        3. Simple app-specific info like:
            1. What screen are we on?
            2. How many thobes are in cart?
            3. The customizations of the items.
            4. We already have the user info
    that's it. no need for anything fancy

"Simplicity and Creativity"


Important:
  • The UI for Admins and Our Team
  • Need to be able to visualize not only elegantly but in a useful easy to 
    understand "graph"
  • The organization of the data
  • Probably will follow this heirarchy:
    • User
    • Session
    • Milestone-Event-Journey(flow)
    • Items in Cart
• At scale there are *countless* creative ways we can leverage this data gold 
  mine to focus our offerings, ux (flow/journey), marketing direction, etc.
• Finally this data can be 10x-ed in its value-as-a-means-to-sales-optimization
